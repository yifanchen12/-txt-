# 小说自下载：网站、手机安装和本地阅读改造提案

日期：2026年11月3日。状态：用户已确认原生 IPA、GitHub 浏览器下载、不依赖电脑；接受先交付供自行签名的 IPA。进入实施。

## 完成标准

1. 网站提供起点、番茄、晋江三个分区，按可核实的官方榜单顺序筛选已配置源可下载的作品；首页、推荐流、搜索结果及本地书库均有封面。
2. 提供安卓可安装 APK，以及用户确认的免 App Store iPhone 安装方式；明确网站安装版与原生 IPA 的区别。安装包、构建成功和真机安装分别报告验证情况。
3. 用户能把书保存到当前设备，断网后打开本地书库继续阅读；提供目录、阅读进度恢复、背景、字号、行距与仿真翻页。

## 已验证的现状与复用

目标项目：`E:\user\Desktop\gpt个人研究项目\小说自下载`，与当前聊天工作目录不同。

- Python 标准库 HTTP 服务、requests 和 BeautifulSoup 已有；没有前端工程或手机工程。
- `novel_archiver/sources.py` 已有起点完本分类、番茄榜单适配；当前配置未启用这些适配，没有晋江适配。
- 当前配置启用 4 个榜单源和 8 个下载源，均声明 authorized。这里只核对配置，尚未逐源验证在线下载。
- `novel_archiver/downloader.py` 已有检索、下载解析、章节抓取和 HTTP 客户端；不重做下载引擎。
- `novel_archiver/archive.py` 已有分类、去重、清单和容量限制。
- `novel_archiver/server.py` 的 `/api/search` 只查电脑本地；`/api/ensure` 会触发下载；不能把它直接用于输入即搜索。
- 当前监听 `127.0.0.1:8765`，手机不能直接访问电脑的回环地址。
- `BookCandidate` 没有专用封面字段。当前没有设备端离线书库、阅读器或应用安装信息。
- 机器可找到 Node.js、npm 和 Java；常用位置没有 Android SDK，尚未确认其他位置，也没有完成移动端构建。

## 界面方向

以小说书城和阅读为中心：暖白背景、深灰文字、少量朱红强调。电脑首页按三站分区呈现封面榜；手机压缩为可切换的分区和单列推荐。搜索结果显示书名、作者、封面、平台及下载状态。阅读页隐藏书城导航，点击中央展开设置和目录。

## 能力与文件边界

以下路径均相对目标项目。

### 榜单、封面和搜索

- 修改 `novel_archiver/models.py`：为封面、平台和榜单位置添加兼容的默认字段，旧清单可继续读取。
- 修改 `novel_archiver/sources.py`：复用起点、番茄解析，增加晋江公开榜单元数据解析和封面提取；只有拿到真实榜单顺序才标注热门排行，失败时显示来源不可用和更新时间。
- 新增 `novel_archiver/catalog.py`：统一书目、同名作者匹配、封面缓存、榜单缓存和下载可用性状态；发现书籍不自动抓取全文。解析到链接与实际成功下载分开记录。
- 修改 `novel_archiver/server.py`：提供前端静态资源、书目接口、按书籍标识取封面及已归档文件的受控读取接口；保持现有 API 兼容。
- 新增 `novel_archiver/web/`：网站首页、三分区榜单、推荐、搜索、书籍详情及下载进度。
- 封面优先使用同书名、同作者的官方/已配置源元数据；失败时使用明确的书名占位封面，不给小说配错误图片。缓存不把来源凭据传给前端。

### 安卓与 iPhone 安装

- 在 `novel_archiver/web/` 增加 manifest、Service Worker、图标和安装说明，作为设备端离线阅读基础。
- 安卓新增 `mobile/` 工程，采用复用网页界面的最小原生容器方案，生成可安装 APK；设备端书库与文件导出应有实际保存路径或导出操作。
- iPhone 交付原生 IPA：GitHub Actions 的 macOS 构建真实 iPhone arm64 应用并打包未签名 IPA，用户自行签名安装。未签名 IPA 不能直接安装，下载页和发行说明明确标注。
- 新增构建和使用文档；不把个人源配置或任何凭据打入安装包。
- 网站和手机复用同一前端。原生手机端通过 Capacitor 原生 HTTP 直接连接书源，联网搜索和下载也不依赖电脑。网页浏览器受跨域规则限制，使用可选云端代理；原有电脑服务保留兼容。

### 本地书库与阅读器

- `novel_archiver/web/` 内实现设备端书库，以 IndexedDB 保存正文、封面和阅读位置；区分“电脑已归档”和“本机已保存”。
- 提供 TXT 导入、编码识别、自动分章，以及从服务器下载后存入设备的路径。以真实配置生成的 TXT 为首要格式；其他格式只在验证能够解析后声明支持。
- 阅读设置包括字号、行距、背景、目录、进度和续读；重新排版后保留正文位置。
- 背景和操作参考可访问的当前起点阅读界面，具体种类需实际核对，不能提前宣称完全一致。
- 仿真翻页包含随手势变化的页角/纸张和背面阴影，并能取消翻页、反向翻页、跨章；不能用普通左右滑动冒充仿真翻页。
- 处理浏览器存储配额失败，保留用户导出备份入口；断网测试必须关闭服务端连接后重新打开阅读器。

## 接口约定

- `GET /api/catalog?platform=&q=&cursor=`：只返回元数据和分页，不因搜索自动下载全文；包括书籍 id、书名、作者、平台、封面地址和可用性状态。
- `GET /api/rankings?platform=`：返回榜单名称、来源时间、官方位置和已匹配的书籍；失败返回可解释的来源状态，不生成示例榜单补位。
- 新的下载请求返回任务 id；查询任务获得排队、下载、完成或失败状态及进度，避免长请求卡住页面。
- 文件和阅读接口接受书籍 id，由服务端映射到书库内文件，拒绝任意路径读取；配置、Cookie 和来源密钥不进入浏览器响应。
- 设备书库用当前设备已保存记录驱动，服务器有文件不等于手机已下载。
- 保留旧 `/api/search`、`/api/ensure`、设置接口、命令行及 Windows 启动方式；新增接口供新版前端调用。

## 已确认的实施决定

- 安卓 APK 和 iPhone 原生 IPA 由 GitHub Releases 提供浏览器下载。用户无现成 iOS 签名材料，明确接受先完成自行签名 IPA。

- GitHub Actions 构建并发布，iOS 不在 Windows 伪造二进制；真实编译结果是交付前提。
